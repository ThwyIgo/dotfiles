* What is this?

A minimal NixOS config that uses LUKS, BTrFS, swap-file, impermanence,
home-manager, disko and secure-boot with TPM auto-unlock.

* Status

Working!

Remarks: Virtual network virbr0 might conflict with host network if
installing on a paravirtualized machine.

* Install steps

1. Enter UEFI/BIOS settings and put Secure Boot into *Setup Mode* (clear/erase Secure Boot keys, keeping Secure Boot enabled if your firmware allows it).
2. Boot nixos-minimal LiveCD.
3. Find a way to put the files from this repository onto the LiveCD
   (suggestions: git clone, curl, usb flash drive) and ~cd~ into it.
4. ~sudo su~.
5. Create your LUKS password using ~printf 'password' > /tmp/luks-passwd.txt~.
6. Check in which disk you want to install your system using ~lsblk~.
7. Change =disko.nix= to make ~disko.devices.disk.main.device~ point
   to the correct device.
8. Change =disko.nix= to make
   ~disko.devices.disk.main.content.partitions.luks.content.passwordFile~
   point to the =luks-passwd.txt= you created.
9. Run disko to format the disk:
   ~nix --experimental-features "nix-command flakes" run disko/latest --
   --mode destroy,format,mount disko.nix~.
10. Copy your configuration files to the persistent directory: ~cp -r /tmp/host/persistent/* /mnt/persistent/~.
    - Make sure you don't copy =luks-passwd.txt=.
11. Generate =hardware-configuration.nix=: ~nixos-generate-config --no-filesystems --root /mnt/persistent/~.
12. Create =user='s password: ~mkpasswd -m sha-512 > /mnt/persistent/etc/nixos/secrets/user-passwd.txt~.
13. (Optional, if ~KEK~ or ~db~ variables already exist in UEFI NVRAM) Remove the immutable flag from ~efivars~ so ~sbctl~ can update them:
    ~chattr -i /sys/firmware/efi/efivars/{PK,KEK,db}-* 2>/dev/null || true~.
14. Install NixOS: ~nixos-install --no-root-passwd --no-channel-copy --flake /mnt/persistent/etc/nixos#nixos~.
    - This automatically generates the Secure Boot keys, enrolls them into UEFI (if in Setup Mode), and signs Limine.
15. Persist the generated Secure Boot keys (since =/= is tmpfs and =preservation= hasn't mounted =/var/lib/sbctl= yet):
    ~mkdir -p /mnt/persistent/var/lib/sbctl && cp -a /mnt/var/lib/sbctl/. /mnt/persistent/var/lib/sbctl/~.
16. Reboot. (Depending on your motherboard, Secure Boot will already be active; if not, enable Secure Boot in UEFI/BIOS settings).

* TPM2 Auto-Unlock for LUKS

This step must be run *once manually after the first reboot* into the installed system (with Secure Boot active and a TPM 2.0 device present). It cannot be done from the LiveCD because PCR 7 changes once the UEFI transitions from Setup Mode to User Mode with Secure Boot enabled.

1. Check the LUKS partition path with ~lsblk -f~ (with disko, it is usually =/dev/disk/by-partlabel/disk-main-luks=).
2. Enroll the TPM2 key bound to PCR 0 (UEFI firmware) and PCR 7 (Secure Boot state/keys):
   #+begin_src sh
   sudo systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=0+7 /dev/disk/by-partlabel/disk-main-luks
   #+end_src
   - Enter your existing LUKS passphrase when prompted.
   - Keep your passphrase keyslot as a fallback in case firmware/Secure Boot state changes.
3. Reboot — LUKS will now unlock automatically without asking for a passphrase on all subsequent boots.

* Verifying IOMMU / PCI Devices

Because =boot.kernelParams= enables strict IOMMU and ~efi=disable_early_pci_dma~, check after booting (and after suspend/resume) that no PCI device failed to initialize:

1. Check kernel logs for errors or IOMMU/PCI faults:
   #+begin_src sh
   sudo dmesg -l err,crit,alert,emerg
   sudo dmesg | grep -iE 'pci|iommu|dmar|amd-vi|probe.*failed|fault'
   #+end_src
2. Verify that essential PCI devices (NVMe/SATA, GPU, network/Wi-Fi, audio, USB) have a ~Kernel driver in use~:
   #+begin_src sh
   nix-shell -p pciutils --run "lspci -k"
   #+end_src
3. Check for failed systemd units:
   #+begin_src sh
   systemctl --failed
   #+end_src
4. If a device fails to initialize or breaks after suspend, try removing ~efi=disable_early_pci_dma~ (or ~iommu.strict=1~ if experiencing I/O slowdowns) from =configuration.nix=.

* Hints

- Add =/persistent/etc/nixos/secrets/= to =.gitignore=.
- Never edit =/persistent/etc/nixos/hardware-configuration.nix= by hand.
- If you ever run out of space in the LiveCD, try running ~nix-collect-garbage~.

* Testing in a Virtual Machine (QEMU)

1. Navigate to the configuration directory:
   #+begin_src sh
   cd persistent/etc/nixos
   #+end_src

2. Build and run the virtual machine:
   #+begin_src sh
   nix run .#nixosConfigurations.nixos.config.system.build.vm
   #+end_src

   /Note: If running on a headless system without a display server, pass =QEMU_OPTS="-nographic"=:
   #+begin_src sh
   nix build .#nixosConfigurations.nixos.config.system.build.vm
   QEMU_OPTS="-nographic" ./result/bin/run-nixos-vm
   #+end_src

* Secure Boot in virt-manager

1. Create a new VM in ~virt-manager~ with the NixOS minimal ISO.
2. On the last step, check *Customize configuration before install* and click *Finish*.
3. In *Overview*:
   - Set *Chipset* to ~Q35~ (required for Secure Boot / SMM).
   - Set *Firmware* to a UEFI Secure Boot option (e.g., ~UEFI x86_64: .../OVMF_CODE.secboot.fd~ or ~OVMF_CODE_4M.secboot.fd~).
   - Click *Apply*.
   - Optional (for LUKS TPM2 auto-unlock): click *Add Hardware* -> *TPM* -> Type: *Emulated*, Model: *CRB*, Version: *2.0*.
   - Click *Begin Installation*.
4. Enter OVMF UEFI setup to put Secure Boot into *Setup Mode* (default OVMF secboot NVRAM may have pre-enrolled keys that block the unsigned NixOS LiveCD):
   - Press =ESC= or =F2= at the TianoCore splash screen.
   - Navigate to *Device Manager* -> *Secure Boot Configuration*.
   - Ensure *Attempt Secure Boot* is checked.
   - Set *Secure Boot Mode* to *Custom Mode*.
   - Open *Custom Secure Boot Options* -> *PK Options* -> *Delete PK* (this puts OVMF into *Setup Mode*).
   - Save (=F10=) and *Reset* the VM so it boots into the NixOS LiveCD.
5. Follow the *Install steps* above (starting from step 3). On the first reboot after installation, Secure Boot will already be active.
6. After logging into the installed system, you can verify with ~sudo sbctl status~ and ~sudo sbctl verify~.
